# LYFE на Railway

Инструкция для деплоя на Railway вместо своего сервера.

---

## Сначала честно про деньги

Railway проще в настройке, но дороже и считает по факту потребления.

| | Railway | Свой VPS |
|---|---|---|
| Настройка | 20 минут, всё в браузере | час, через терминал |
| Цена | Hobby 5 $/мес, куда включено 5 $ ресурсов | 4,5 € фиксированно |
| Реально выйдет | два сервиса и база круглосуточно — обычно 10–20 $/мес | те же 4,5 € |
| HTTPS | автоматически | автоматически через Caddy |
| Обновление | git push | `./deploy/update.sh` |

Плата за удобство — примерно вдвое-втрое. Для одного проекта это терпимо;
просто не удивляйся счёту в конце месяца. Всё, что здесь описано, можно потом
перенести на VPS — код одинаковый.

---

## Что должно получиться

В проекте Railway будет **три сервиса**:

```
Postgres          база (создаётся кнопкой)
lyfe-bot          Telegram-бот
lyfe-web          DJ-экран, сканер, админка ивентов
```

Оба сервиса — из одного репозитория, но с **разными командами запуска**.
Это ключевой момент: если не поменять команду у второго, он поднимет второго
бота, и Telegram начнёт выдавать `Conflict: terminated by other getUpdates`.

---

## 1. Один бот в один момент времени

Прежде всего останови локальный на макбуке:

```bash
pkill -f "lyfe.bot.main"; pkill -f uvicorn
```

Telegram отдаёт обновления только одному потребителю. Пока работает второй,
ни один не работает нормально.

---

## 2. База

В проекте Railway: **New → Database → Add PostgreSQL**.

Больше ничего настраивать не нужно. Railway сам создаст переменную
`DATABASE_URL`, а код умеет её читать — приводит к нужному драйверу и убирает
параметры, которые asyncpg не понимает.

---

## 3. Сервис бота

**New → GitHub Repo →** твой репозиторий.

В настройках сервиса:

**Settings → Deploy → Custom Start Command:**

```
bash scripts/start_bot.sh
```

Этот скрипт сначала накатывает миграции, потом запускает бота. Миграции
выполняются **только здесь**, чтобы два сервиса не делали это одновременно.

**Variables** — добавь:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен от BotFather |
| `ADMIN_SECRET_KEY` | новая длинная случайная строка |
| `DATABASE_URL` | ссылка на базу, см. ниже |
| `POINTS_VOTE` | `0` |
| `COST_PRIORITY_TRACK` | `40` |
| `DEFAULT_LANGUAGE` | `ru` |

`DATABASE_URL` не набирай руками. В Railway есть подстановка ссылок: нажми
**Add Variable → Add Reference** и выбери `DATABASE_URL` от сервиса Postgres.
Тогда при смене пароля базы ничего не сломается.

Секрет сгенерируй на макбуке:

```bash
openssl rand -hex 32
```

---

## 4. Сервис веба

**New → GitHub Repo →** тот же репозиторий ещё раз.

**Settings → Deploy → Custom Start Command:**

```
python -m lyfe.web
```

Порт брать не надо — Railway передаёт его в `PORT`, код это учитывает.

**Variables** — те же, что у бота: `BOT_TOKEN`, `ADMIN_SECRET_KEY`,
`DATABASE_URL` (тоже ссылкой). Плюс:

| Переменная | Значение |
|---|---|
| `ENV` | `prod` |

`BOT_TOKEN` нужен и здесь: именно веб-сервис отправляет пуш «твой трек играет»
и подтверждение прихода.

**`ADMIN_SECRET_KEY` должен быть одинаковый у обоих сервисов.** Он подписывает
и сессии администраторов, и QR в LYFE PASS. Разные значения — и сканер не
примет ни один код.

**Settings → Networking → Generate Domain.** Получишь адрес вида
`lyfe-web-production.up.railway.app` с готовым HTTPS. Камера в сканере
заработает.

---

## 5. Первый запуск

После того как оба сервиса поднялись, надо заполнить базу. Проще всего через
Railway CLI с макбука:

```bash
npm i -g @railway/cli
railway login
cd ~/Desktop/lyfe
railway link
```

Выбираешь проект и сервис `lyfe-bot`, дальше:

```bash
railway run python scripts/seed.py
railway run python scripts/seed_rewards.py
railway run python scripts/create_admin.py max "надёжный_пароль" SUPER_ADMIN
railway run python scripts/create_admin.py dj "пароль_диджея" DJ
railway run python scripts/create_admin.py door "пароль_входа" MODERATOR
```

`railway run` подставляет переменные окружения из облака, поэтому команды
работают с боевой базой, хотя запускаются с твоего компьютера.

Если CLI ставить не хочешь — в Railway есть кнопка **Deploy → Run Command**
у сервиса, туда вводятся те же команды без префикса `railway run`.

## 6. Проверка

По порядку, каждый пункт до следующего.

| # | Что проверяешь | Как понять, что хорошо |
|---|---|---|
| 1 | Логи `lyfe-bot` | `LYFE bot starting as @lyfeparty_bot`, ошибок нет |
| 2 | Логи `lyfe-web` | `Uvicorn running`, ошибок нет |
| 3 | Бот в Telegram | `/start` отвечает, выдаёт `LYFE #0001` |
| 4 | `https://твой-адрес/events` | Пускает под `max`, видно ивенты |
| 5 | Добавляешь трек в боте | Появляется в TOP |
| 6 | `https://твой-адрес/` под `dj` | Трек в списке, жмёшь PLAYED |
| 7 | Через 15 секунд | Пуш «🔥 ТВОЙ ТРЕК СЕЙЧАС ИГРАЕТ» |
| 8 | `https://твой-адрес/scan` под `door` | **Камера включается** |
| 9 | Сканируешь свой LYFE PASS | Зелёный экран, `+10 LYFE POINTS` |

Восьмой пункт — то, ради чего вообще нужен был деплой. На макбуке по
локальному адресу камера не работала никогда.

## 7. Обновления

```bash
git add . && git commit -m "что изменил" && git push
```

Railway пересоберёт оба сервиса сам. Миграции накатятся при старте бота.

---

## 8. Если что-то не так

| Симптом | Причина | Решение |
|---|---|---|
| `Conflict: terminated by other getUpdates` | Бот запущен дважды | Выключи локальный; проверь, что у веб-сервиса команда `python -m lyfe.web`, а не команда по умолчанию |
| `relation ... does not exist` | Миграции не прошли | Логи `lyfe-bot` при старте, там вывод alembic |
| Сканер: «Код не наш» | Разные `ADMIN_SECRET_KEY` у сервисов | Сделай одинаковыми, пересобери |
| Камера не включается | Открыл по `http` | Только `https://` |
| `invalid dsn` или ошибка драйвера | `DATABASE_URL` вписан руками с опечаткой | Замени на Reference от Postgres |
| Веб не открывается | Не сгенерирован домен | Settings → Networking → Generate Domain |

Логи смотри во вкладке **Deployments → View Logs** у нужного сервиса.
